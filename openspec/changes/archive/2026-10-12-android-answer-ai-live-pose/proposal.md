# 成功页活立绘改用 AI 生成的微动循环（Wan2.2 视频模型）

## 为什么改

v1.31.0 的活立绘是"离线像素波动"（`tools/gen_pose_anim.py`：横向带状位移 + 呼吸凸起），
用户实测反馈"**视觉上不太自然**"——本质是把静态图按行错位，没有真实的动作语义。

社区方案调研后确定：用开源视频模型 **Wan2.2 I2V-A14B**（fp8_scaled + 4 步 Lightning LoRA）
以「**首尾帧喂同一张立绘**」的方式生成微动循环，可做到：
1. 动作是模型理解角色后生成的（呼吸、身体起伏、发丝与尾巴摆动），观感自然得多；
2. **构造级无缝循环**：首尾同图，回放不跳帧（不需要乒乓拼接）；
3. **保角色**：`start_at_step=0` + 官方配方（`ModelSamplingSD3 shift=5` / `steps=4` / `cfg=1` / `euler+simple`）下，
   与原图差异约 11/255 —— 只微动、不换人；
4. 单套成本：5070 Ti 上约 90 秒一发（416×768×49 帧）。

## 保持不破的既有契约

- **仍然是动画 WebP + 系统 `ImageDecoder`**：零第三方依赖、API<28 回退静图摇摆，全部不变。
- **仍然透明**：视频模型没有透明通道，所以生成后**用原始立绘的 alpha 当遮罩**逐帧合成
  （源立绘 935×1682 与 App 显示比例 935:1682 完全一致，构图对齐，无需抠色）；
  这样立绘仍浮在主题卡片之上，深色主题不会出现矩形色块。
- **体积可控**：实测 49 帧/422×760/q70 约 1.9MB、25 帧（12fps）约 1.0MB、17 帧（8fps）约 0.7MB；
  取 **25 帧 / 12fps / 422×760 / q70 ≈ 1.0MB/套**（六套合计约 6MB），与 v1.31 素材同尺寸契约。

## 方案

1. `tools/prep_pose_ai.py`：把六套 `pose_*.webp` 归一化为生成用参考图（垫平色底 416×768）与膨胀遮罩；
2. `tools/gen_pose_ai.py`：提交 ComfyUI（首尾同图 FLF2V，4 步 Lightning）→ 拉回结果 → 套遮罩 → 输出透明动画 WebP；
3. 素材仍内置于 `res/raw/pose_anim_*.webp`，主题映射不变（day→maid / night→serious / sakura→shy /
   matcha→confused / starry→starry / caramel→cheerful）；
4. 生成管线跑在台式机 ComfyUI（`F:\AI\comfy-git`），切换与判卷联动由 skill `gpu-mode-switch` 维护。

## 验收

- 六套主题各出一套素材，帧数/尺寸/体积符合上表；
- 遮罩边缘无矩形背景、深色主题无穿帮（贴洋红底目视 + 透明像素占比检查）；
- 流水线 `verify/dsh-app-verify.ps1 -Deploy` 9/9；
- 真机：六套主题分别答一题，动作为自然的微动循环、无缝、无跳帧。
