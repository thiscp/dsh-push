# 窄屏侧栏发现与几何修复：把 spec 追平代码三轮

## Why

`内置浏览器提问卡窄屏防塌陷` 这条 requirement 自 v1.32.15 起已被改过三轮（D2 修挤压、D10 几何认侧栏、D11 覆盖层形态、v1.32.18 两道闸），**但 spec 一直停在第一轮**：它只写「侧栏不占用网格列去挤压内容列」与「展开态以浮层呈现」，没有写下述任何一条**代码里已经存在**的判据：

- 三级优先发现侧栏（类名锚点 → 结构臂 → 指纹臂），把手只做否决仲裁；
- 候选宽度带 **96px ≤ w ≤ vw+2** 与**高度天花板 1.25vh**（真机正文子树 4.35vh、侧栏链 1.00vh；没有天花板就会把 0.92 写到聊天根 = v1.32.6 壁纸红线）；
- 「饥饿兄弟列」的 **40px 盒子下限**（真机被挤正文列 80×671 必须算数，8px 拖拽把手不得被当成列）；
- 撤销语义与其**自锁副作用**（撤销后侧栏回到页面自己的满屏宽覆盖层 ⇒ 「按宽度认侧栏」随我们自己的写入而失效，这正是 D10 的根因）；
- 发现与写入分离（`bwFind` 只发现、`bwGeomFix` 只修挤压且只吃结构臂、`bwAlpha` 只改底色）；
- **v1.32.18 两道闸**：候选必须真的装着侧栏内容（闸 A）；轨道下标按侧栏在外壳里的元素子节点序号定、不按宽度猜，序号越界则撤销不钉（闸 B）。

spec 落后的代价已经付过一次：**v1.32.17 的 P1**（笔电宿主聊天列被钉成 56px、正文一字一行）穿过 9/9 到达用户真机——因为 spec 与流水线都没有「聊天列宽」这一项断言。

## What Changes

- **MODIFIED** `内置浏览器提问卡窄屏防塌陷`：9 条既有 Scenario **逐字保留**，补入上述判据的新 Scenario（三级优先、高度天花板 + 内容闸、40px 下限、按序号钉轨与越界撤销、撤销语义与自锁副作用、发现与写入分离、无类名宿主的去抖观察器），并**点名一处行为变化**：`__bwSbEl` 现在也会由指纹臂发布 ⇒ 玻璃化注入的 `isSb` / `skipBg` 两条臂在 vm1 上会开始排除该元素（这是我们想要的效果，但属行为变化）。
- 新增一条验收 Scenario：改动窄屏几何 MUST 过「每宿主 × 收起/展开」四态几何矩阵（`verify/geom-matrix.mjs`，已是发布流水线第 10 项检查，FAIL 挡住发版）。

## Impact

- Affected specs: `companion-app`（MODIFIED 一条 requirement）
- Affected code: `android-app/app/src/main/java/xyz/cpyh/dshpush/WebActivity.kt` 注入段——**本变更不改代码**，只把 spec 追平已发布的 v1.32.18 代码
- Affected verify: `verify/geom-matrix.mjs`、`verify/extract-injected-js.mjs`、`verify/dsh-app-verify.ps1`（第 10 项检查，已在 master）
- 判据表与实测数字见 `android-app/GLASS-OVERLAY.md` §11.11 / §11.14；本 delta 里每个阈值都能在代码里找到（96 / vw+2 / 0.6vh / 1.25vh / 40px / +40 / 250ms）
