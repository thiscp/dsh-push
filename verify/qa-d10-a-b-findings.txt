== ROOT CAUSE (measured, not inferred) ==
bwFind() rule (1) accepts a sidebar candidate only when  left<=2 AND height>=60%vh AND 96px <= width <= vw*0.9.
At vw=360 that upper bound is 324px. On this host the expanded narrow-screen sidebar is **full viewport width**:
  hHd-Xa_root (sidebar root)          360x671  pos static  x=0   -> 360 > 324, rejected
  pI_x6G_sidebarCol (its column)      360x671  pos static
  pI_x6G_frame (grid shell)           360x671, gridInline empty, computed tracks "360px" (a SINGLE track)
qa-d10-diag.json lists every element with left<=2 and height>=60%vh: 10 of them, ALL over90 (widths 353..360).
**There is no element anywhere in the document inside the [96px, 324px] band**, so bwFind() can never find a sidebar here.
That is self-reinforcing: the old build only ever had a 280px-wide sidebar because its own geometry path pinned width:280px
(the control arm still shows that leftover inline width: 280px). The new build never pins, because it never discovers.
Everything downstream of rule (1) would actually work if the width bound were relaxed:
  rule (2) shell: hHd-Xa_root -> pI_x6G_sidebarCol (block, 1 child) -> pI_x6G_frame (grid, 3 tall children) = shell, col = sidebarCol, flush left  OK
  rule (3) tall sibling: pI_x6G_handle 8x671 at x=276 (inline left: 280px) is <35%vw and >=50%vh => ok=true, starved=true  OK
  expanded flag for a geometry host is g.sbExpanded = (sidebar width >= rail+40) = (360 >= 96) = true => bwAlpha would write 0.92.
CAUTION for whoever relaxes the bound: the conversation subtree is 353 wide and 2922 tall (4.35 x vh) and also sits at left<=2
(wSkVaW_viewArea / EvIC1a_frame / EvIC1a_root / EvIC1a_scroll, all 353x2922). Rule (1) keeps the NARROWEST candidate, so a
bound of vw*1.0 or more would pick the conversation subtree instead of the sidebar and write 0.92 on the chat root -
that is the v1.32.6 wallpaper red line (the synthetic suite S1/S2/S4/S6/S8 guards exactly this).
Suggested discriminator (developer decides): keep the width relaxation but add a height ceiling, e.g. candidate height
<= vh*1.25, which keeps the sidebar (671 = 1.00 x vh) and rejects the conversation subtree (2922 = 4.35 x vh).
A class-free structural anchor is also available: pI_x6G_handle with inline left: 280px is the page own drag handle that
marks the sidebar column boundary (the page itself thinks the sidebar is 280 wide even though the column is 360).
