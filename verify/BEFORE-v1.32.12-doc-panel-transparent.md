## lead 的初判（**待真实 DOM 证实/证伪，不许直接照此改**）

**首要嫌疑**：文档预览面板很可能是个**大容器**（`w>vw*0.5 && h>vh*0.5`）⇒ 落进
**大容器 `transparent` 分支**（那是给"壁纸唯一通道"设计的）⇒ **被设成全透明**，
比普通面板的 `0.45` **更透**，与截图观感吻合。

**次要嫌疑**：它没过大容器阈值 ⇒ 走普通 `0.45` 分支 ⇒ 对**整页阅读器**而言 0.45 太薄。

**⇒ 两者修法完全不同，必须先拿到真实元素的 computed 值与祖先链再定。**
（**这正是一句教训**：v1.32.11 我已因"凭截图推断数值不够"被实测推翻过一次，这次先取实测。）

## 待证清单（developer 侦察必答）

1. 该面板的**真实 class 哈希** / `role` / `position` / `z-index` / 宽高（占视口百分比）；
2. `getComputedStyle().backgroundColor` 与**内联**值（是否被注入成 `transparent` 或 `0.45`）；
3. **祖先链逐层**（面板 → `body`）的 alpha 与 `background-image`（注意：只读 `backgroundColor`
   会漏掉渐变底 —— v1.32.11 的祖先链探针已证明这个坑真实存在）；
4. 它是否命中大容器分支（给出算术：`w>vw*0.5` 与 `h>vh*0.5` 各是否成立）；
5. **与"壁纸通道容器"的可区分结构特征**（这是修法的关键）；
6. 顺带确认：同一面板在**差异视图**（`+5 -5`）与**普通阅读视图**下是否同一元素。
