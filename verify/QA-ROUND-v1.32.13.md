## 6. 对抗探针（自加 ≥1 条新角度）

### QA-A31 **多个代码块同屏 + 阈值两侧分流**（本轮新角度）
**角度**：同屏 **10 个** `md-code-block`，**只有 1 个**越过 `50%×50%` 阈值。
新判据 `isCB` 是**按"后代里大容器数量"**判定的，最可能坏的形态就是**"把一个容器里所有代码块一刀切"**——
要么把 9 个矮块一起升到 1.0（**过度提亮**），要么漏掉那 1 个大块（**该亮没亮**）。

**实测**：
```

bigAlphas   = [1]        ← 大块全部 1.0（该亮的亮了）
smallAlphas = [0.45]     ← 矮块全部 0.45（没有一个被误提亮）
smallHeights= [182,163,125,144,182,87,296,87,144]   ← 全部 < 335.5
bigSizes    = ["331x524"]
```
⇒ **阈值两侧分流精确**：大块 1 个命中 `isCB` ⇒ 1.0；9 个矮块全部保持 0.45。**PASS**

### QA-A32 **注入 vs 重渲染竞态**（本轮新角度，**抓到真缺陷**）
**角度**：玻璃化注入是**一次性写内联样式**，而页面是 React 应用、**会替换 DOM 节点**。
新节点**不带内联样式** ⇒ 在**下一次 `apply()` 到达之前**显示**原生色**。
若原生是**不透明**的（`Dc7zOa_root` 原生就是 `rgb(255,255,255)`），这段窗口内**壁纸会被盖住**。
**这是"注入类改动"通用的一类风险，本库此前没有对应用例。**

**实测**：**命中**（见 §8）—— 帧内 `alpha=1 / inline=''`（内联被抹掉），**并已截图捕获实锤**。

### 7.3 ⚠️ 一条更值得注意的细节：`t=2987ms` 的内联是 `rgb(255,255,255)`（**注入自己写的白**）

`t=2987/3498ms` 的 inline 是 **`rgb(255,255,255)`（带值，非空）**，而 `touched` 只有 8
—— 说明**这一次**是**注入把它写成了原生白色**（走的应是"取原生色相再写回"的路径），
而不是"还没注入"。
**这意味着该层在不同 apply 轮次里可能先被写成白色、再被写成 transparent**，
即 **`Dc7zOa_root` 在同一会话内经历过 `rgb(255,255,255)` → `transparent` → （节点替换）原生白 → `transparent`**。
**对 `Dc7zOa_root`（84%×100% 的聊天根）而言，任何一轮被写成不透明白，都会在该轮盖住壁纸。**
⇒ **建议 developer 复核**：`Dc7zOa_root` 是否应被**显式排除**在"取原生色相回写"的路径之外
（它属**布局/滚动容器**，不是内容块；其原生的白是**兜底背景**，之所以能被 v1.32.6 的通道保住，
正是因为注入把它设成 `transparent`——**一旦某轮写成白色，就等价于把通道关掉一瞬**）。
