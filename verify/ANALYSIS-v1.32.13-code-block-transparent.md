### 6.5.2 ① 判据：**只用 `innerBig ≤ 2`**（**不**做"类名 OR"）

**裁定：只用结构判据 `big && !isAnchor && nativeOpaque && innerBig<=2`。**

**为什么否掉 developer 提的"类名 OR innerBig≤2"**（我改了他的建议，理由如下）：
1. **"OR 类名"是在增加一条脆弱路径**，与 developer 自己举的 v1.32.5 教训（上游改 CSS-module 即失效）**同源** ——
   **`innerBig` 完全不依赖类名**，所以它对上游改名**天然免疫**；再加类名 OR **只会引入一个会静默失效的分支**；
2. **单路径更好验证**：`wouldChange=1` 是**单判据**下的实测结果；OR 之后必须重新实测并重跑五红线，
   收益是"另一种冗余"，**但本轮没有任何证据表明需要这种冗余**；
3. **余量充足**：目标 `innerBig=2` vs 三容器 `41/42/70` ⇒ **20 倍余量**，判据**稳健**（不是"刚好卡住"）；
4. **失败方向是安全的**：万一将来某内容块 `innerBig>2`（如内部嵌了宽表），**结果是"漏修"**（用户仍见透），
   **不是"误修"**（壁纸消失）。**在本仓，漏修可再开一轮，误修等于复现 v1.32.6** ⇒ **宁可漏，不可误**。

**⇒ developer 请按单判据落地**；`md-code-block` 类名只作为**诊断信息**打进探针（便于下轮定位），**不进代码分支**。

### 6.5.3 ② alpha = **`1.0`**（批准）

同 developer 与我的一致倾向：**它是内容（读者要长时间看代码），不是"浮在背景上的装饰"**；
